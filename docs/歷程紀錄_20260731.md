# Day 5 — 電源鏈分析與 U-Boot 網路修復（2026-07-31）

**目標：** 理解開發板的離散電源架構；接著從頭到尾修復 U-Boot 乙太網路故障（`Could not get PHY` / `address not set`）：自訂 DTS、UUU 崩潰恢復、基於原理圖的除錯，以及最後的 MAC 位址修復，讓 `eth1 [PRIME]` 正式上線。

---

## 1. 電源鏈分析

ATK-IMX6U 核心板採用**離散電源方案（Discrete Power Solution）**——每一路電源由獨立穩壓 IC 產生，而非 I2C 控制的 PMIC。

```
[DC5V 輸入]
   ├── U7 (ME6209A33M3G LDO) ──► VDD_SNVS_3V3 ──► SoC SNVS 域（RTC/低功耗）
   │                                    │
   │                        SoC 硬體拉高 PMIC_ON_REQ
   │                                    ▼
   ├── U8 (TMI3113 DCDC) ◄── EN 腳位  ──► DCDC_3V3（主 3.3V）
   │                                    │
   │                        DCDC_3V3_PG (Power Good)
   │                                    ▼
   ├── U6 (MT3420B) ──► SOC_IN (1.2V, ARM Core)
   ├── U11 (MT3420B) ──► DRAM_1V35 (1.35V, DDR3L)
   ├── U9 (TMI6050) ──► VCC_SD (3.3V)
   └── U12 (XC6206P282MR) ──► NVCC_CSI (2.8V)
```

關鍵結論：

- `PMIC_ON_REQ` 由 SNVS 域的**純硬體狀態機**拉高，不需 CPU 執行任何程式碼（解決「先有雞還是有蛋」的電源問題）。
- 板上所有電源 IC **皆無 I2C 介面**，電壓由電阻分壓硬體固定。→ U-Boot 不需要（也無法）控制 PMIC，因此 `CONFIG_DM_PMIC` 維持關閉。
- Reset 由 **MAX809R**（Reset Supervisor）產生，3.3V 穩定後約 **~140ms** 延遲才釋放 `POR_B`。
- 軟體關機時 CPU 寫 `SNVS_LPCR` 拉低 `PMIC_ON_REQ` 才切斷主電源。

MT3420B 為純類比降壓 IC（SOT23-6，無暫存器介面），僅能由 EN 腳（硬體接 `DCDC_3V3_PG`）控制，`VOUT = 0.6V×(1+R1/R2)`。

## 2. U-Boot DDR3L 建置與 boot0 燒錄

由於 PMIC 完全獨立，燒錄含自訂 DDR3L DCD 的 U-Boot 是安全的。建置流程（Buildroot 工具鏈，GCC 12.3.0）：

| 步驟 | 動作 | 結果 |
|:---:|------|:---:|
| 1 | 備份原版 `imximage.cfg` → `imximage.cfg.orig` | ✅ |
| 2 | 套用 Nanya NT5CC256M16EP-EK DDR3L cfg | ✅ |
| 3 | `make mx6ull_14x14_evk_defconfig` | ✅ |
| 4 | `make CROSS_COMPILE=arm-buildroot-linux-gnueabihf- -j4` | ✅ `MKIMAGE u-boot-dtb.imx` |
| 5 | 驗證 DCD（MR2/MR3/MR1/MR0 + ZQ cal 共 5 筆指令） | ✅ |

燒錄至 eMMC boot0（經 SSH，板子在 Linux 中執行）：

```bash
echo 0 > /sys/block/mmcblk1boot0/force_ro
dd if=u-boot-dtb.imx of=/dev/mmcblk1boot0 bs=1K seek=1 conv=fsync
echo 1 > /sys/block/mmcblk1boot0/force_ro
# 讀回比對（offset 1KB 起，617472 bytes）
```

boot0 佈局：前 1KB 全 0，IVT 位於 0x400（= `u-boot-dtb.imx` 的 offset 0）。

## 3. DTB 載入修復（Phase 1 / Phase 2）

燒錄後 Linux 載入錯誤的 device tree。

- **Phase 1（驗證）：** U-Boot 提示符下 `setenv fdt_file imx6ull-atk.dtb` + `saveenv` → Linux 開機正確（UART3 / 雙網卡 / SPI 全正常）。
- **Phase 2（永久）：** 修改 `include/configs/mx6ullevk.h` 第 89 行（先備份 `.orig`）：

```c
"fdt_file=undefined\0"  →  "fdt_file=imx6ull-atk.dtb\0"
```

NXP 的 `findfdt` 只會在 `fdt_file=undefined` 時覆寫 → 即使環境變數被清空，板子也永遠載入我們的 DTB。

---

## 4. 自訂 U-Boot DTS 與崩潰（Phase 3 / Phase 4）

- **Phase 3：** 複製 `DTS/imx6ull-atk.dts` 到 `uboot-imx/arch/arm/dts/imx6ull-atk.dts`，加入 `#include "imx6ul-14x14-evk-u-boot.dtsi"`，註冊到 DTS Makefile，並在 defconfig 設 `CONFIG_DEFAULT_DEVICE_TREE="imx6ull-atk"`。
- **Phase 4：** 恢復 `phy-supply` 後觸發**無限重啟崩潰**（`Get shared mii bus on ethernet@2188000` 之後 `undefined instruction`）——這是 U-Boot 對**共享 MDIO bus**（`ethphy0`/`ethphy1` 都宣告在 fec2 的 `mdio` 節點下，fec1 又引用 `ethphy1`）的處理 bug。

---

## 5. UUU 緊急恢復

板子被崩潰版本搞死後，透過 Serial Downloader 模式救回：

```
uuu_version 1.2.39
SDP: boot -f _flash.bin          # 我們自己的正常版 U-Boot（含 DDR3L DCD）
FB: ucmd mmc dev 1 1             # 選取 eMMC boot0 硬件分區
FB: download -f boot0.bin
FB: ucmd mmc write 0x83800000 0x0 0x2000   # 4MB = 0x2000 blocks
FB: ucmd mmc dev 1 0
FB: done
```

踩過的坑：

- UUU 腳本首行必須 `uuu_version 1.2.39`，且要在含 `uuu.auto` 的目錄執行。
- MFG SPL（`u-boot-with-spl.imx`）會 `Unsupported Boot Device` → 改用**我們自己編譯的** U-Boot。
- `FB: flash bootloader` 因無 `CONFIG_FASTBOOT_MMC_BOOT_SUPPORT` 失敗 → 改用 U-Boot 原生命令（`mmc dev 1 1` + `mmc write`）。

---

## 6. 方案 E：U-Boot DTS 停用 fec1

崩潰根因：fec1/fec2 共享 MDIO bus（U-Boot bug）。在 U-Boot 的 `imx6ull-atk.dts` 中繞過：

```c
&fec1 { status = "disabled"; };
```

之後：崩潰消失，開機 log 只剩 `Could not get PHY for FEC1: addr 1`（fec2 的 MDIO bus 名是 `FEC1`，因為其 device sequence 為 1）。

---

## 7. 原理圖調查（決定性證據）

用 `pdftotext` 提取核心板與底板原理圖全文：

1. **PHY 在底板上**（U14/U15 = SR8201F），不在核心板。
2. **PHY reset 腳有 10K 上拉**到 3.3V → PHY 預設不處於 reset 狀態（解釋了為何 reset 配置錯誤時 Linux 仍 Working）。
3. **底板 J2 是權威標示：** `J2_9 = SNVS_TAMPER8 (GPIO5_IO08) = ENET2_RST`、`J2_10 = SNVS_TAMPER7 (GPIO5_IO07) = ENET1_RST`。
4. NXP dtsi 位址對應：`fec1 = ethernet@2188000 = ENET2`、`fec2 = ethernet@20b4000 = ENET1`。

---

## 8. phy-reset-gpios 交叉配反修正

比對原理圖後發現：3 份 `imx6ull-atk.dts`（GitHubUpload / linux-imx / uboot-imx）的 `phy-reset-gpios` **交叉配反**：

| 節點 | 錯誤（原） | 正確（J2） |
|------|:---:|:---:|
| fec1 (ENET2) | `<&gpio5 7>` ❌ | **`<&gpio5 8>`**（ENET2_RST=TAMPER8） |
| fec2 (ENET1) | `<&gpio5 8>` ❌ | **`<&gpio5 7>`**（ENET1_RST=TAMPER7） |

pinctrl 群組定義其實正確——交叉的只是 GPIO 編號。3 份檔案同步修正，Linux DTB 重新部署（36512 bytes）。

## 9. 最終網路修復

### 9.1 PHY ID 確認：`0x001CC816`

在 U-Boot 提示符手動操作 MDIO（寫 `MII_DATA` 命令再讀回）：

| 暫存器 | 讀值 | SR8201F_VB Datasheet（Table 13/14） |
|--------|:-----:|:---:|
| reg0 (BMCR) | `0x3100` | 標準 BMCR（100M + AN） |
| reg1 (BMSR) | `0x7869` | 標準 BMSR |
| reg2 (PHYID1) | `0x001C` | OUI[21:6] = `001Ch` ✅ |
| reg3 (PHYID2) | `0xC816` | OUI_LSB(110010) + Model(000001) + Rev(0110) ✅ |

> **SR8201F 完整 PHY ID = `0x001C_C816`** —— 與 datasheet 完全一致。
> （有趣的是：Linux 回報 `0x00110140`，與 datasheet 不符，但不影響功能，因為使用 generic PHY driver。）

### 9.2 真正擋路的是：MAC 位址

PHY 回應正常後，剩下的唯一錯誤：

```
Error: ethernet@20b4000 address not set.
```

`net/eth-uclass.c` 在「環境變數（`ethaddr`）與驅動提供的 MAC 都無效」時拒絕該設備。OTP fuse 未燒 MAC（Linux 一直用隨機 MAC）。修復：

```kconfig
CONFIG_NET_RANDOM_ETHADDR=y    # 加入 configs/mx6ull_14x14_evk_defconfig
```

同時移除 `fec_mdio_read()` 中的 `MDIO_DBG` 除錯 printf。

### 9.3 結果

```
Net:
Warning: ethernet@20b4000 (eth1) using random MAC address - b2:82:77:4e:9a:cb
eth1: ethernet@20b4000 [PRIME]

=> ping 192.168.1.1
Using ethernet@20b4000 device
host 192.168.1.1 is alive
```

固定 MAC 持久化：

```text
setenv eth1addr 00:1c:c8:00:00:01
setenv ipaddr 192.168.1.100
saveenv
```

開機後 Linux `eth0` 顯示 `00:1C:C8:00:00:01`（U-Boot 將環境變數 MAC 修補進 DTB）。建置產物：`u-boot-dtb.imx`（629,760 B，MD5 `32661e6f...`，時間戳 `Jul 31 2026 - 11:44:31`）。

| 誤導實驗（ANATOP bit21、ECNTRL、PAD 0x0334） | ✅ 已排除 | Linux vs U-Boot 暫存器快照比對，無相關差異 |

## 學習重點

1. **U-Boot 與 Linux 各自獨立 DTS 生態系** —— 同基底 dtsi、不同頂層 DTS，修改必須兩邊同步。
2. **離散電源板不需 U-Boot 控制 PMIC** —— `CONFIG_DM_PMIC` 維持關閉；DCD 只影響 DDR 初始化。
3. **`address not set` 是 MAC 問題不是 PHY 問題** —— `CONFIG_NET_RANDOM_ETHADDR=y` 一行解決。
4. **SR8201F PHY ID = `0x001CC816`** —— datasheet 才是權威。
5. **eMMC boot0 佈局**：前 1KB 未用、IVT 在 0x400（=`u-boot-dtb.imx` offset 0）——可用 `dd bs=1K seek=1` 或 4MB UUU 映像燒錄。
6. **燒錄前務必備份 boot0**；UUU 恢復流程是板子變磚時的救命稻草。
