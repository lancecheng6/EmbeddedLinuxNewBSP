## 1. NXP BSP Download and Exploration

### Done
Downloaded `LF_v6.18.2-1.0.0_images_IMX6UL7D.zip`. Contents:
- `zImage` (10MB) — pre-built kernel
- `u-boot-imx6ull*.imx` — multiple U-Boot binaries
- `*.dtb` — multiple Device Tree blobs
- `*.uuu` — MfgTool flashing scripts

### Problem
This is a pre-built Yocto image — **no source code**. Cannot customize with Buildroot.

### Solution
Abandon the pre-built images. Build everything from source:
1. `git clone` Buildroot 2024.02
2. `git clone` NXP Linux kernel `lf-6.6.y`
3. `git clone` NXP U-Boot `lf_v2023.04`

## 2. Buildroot Environment Setup

### Done
Created directory structure. Backed up board DTBs, zImage, and rootfs to `board_backup/`.

### Problem
**BR2_LEGACY error**
A custom `atk_imx6u_min_defconfig` failed Buildroot 2024.02's legacy config check. `BR2_KERNEL_HEADERS_AS_KERNEL` was removed in 2024.02.

### Solution
Use `freescale_imx6ullevk_defconfig` as base with minimal changes:
- Disable kernel build (manage manually)
- Disable U-Boot build (manage manually)
- Set kernel headers to v6.6
- Toolchain built successfully (GCC 12.3.0)
- Rootfs built successfully (BusyBox, 15MB)

## 3. Kernel Minimal Configuration

### Done
Created `kernel-minimal.fragment` to keep UART, eMMC, FEC and disable DRM, USB, SOUND, GPU, WDT, etc.

### Problem
`# CONFIG_NET is not set` was mistakenly written in the fragment, causing **no network support**. First boot showed: `ifconfig: socket: Function not implemented`.

### Solution
Use `savedefconfig` workflow:
1. `make imx_v6_v7_defconfig`
2. Manually disable unnecessary options
3. `make savedefconfig` → produce minimal diff defconfig
4. Save as `kernel_atk_imx6u_defconfig_final`

## 4. Deploying to the Board

### Done
Compiled U-Boot, kernel, and DTB. Needed to copy files to boot partition (mmcblk1p1).

### Problems

#### 4.1 SSH Host Key Mismatch
Windows OpenSSH rejects `ssh-rsa` (disabled by default); board's dropbear only offers RSA key.
**Fix:** `ssh -o HostKeyAlgorithms=+ssh-rsa`

#### 4.2 SSH Password Auth Failed
Buildroot rootfs overwrote `/etc/shadow`. Board's password became blank, but dropbear rejected blank passwords.
**Fix:** Login via COM7, set password with `passwd`, or use `sshpass -p ''`.

#### 4.3 COM7 File Transfer Failed
Attempted to transfer 7.7MB zImage via COM7 using base64. Shell heredoc corrupted by terminal, echo line length limits, printf quoting issues — file was always damaged.
**Fix:** Use USB flash drive + u-boot `fatload`/`fatwrite` commands.

#### 4.4 COM7 Special Character Issues
Even a 36KB DTB couldn't be transferred reliably via COM7.
**Fix:** Use SSH + SCP (fast once network is up).

## 5. PHY Reset Debugging

### Done
Configured FEC `phy-reset-gpios` to control the PHY reset pin.

### Problems (three wrong guesses)

| Attempt | fec1 reset | fec2 reset | Result |
|---------|-----------|-----------|--------|
| **Guess 1** | `&gpio5 1` | — | PHY not responding |
| **Guess 2** | `&gpio5 8` | — | PHY not responding |
| **Guess 3** | `&gpio5 7` (swapped with fec2) | `&gpio5 8` | PHY not responding |
| **Original DTS** | `&gpio5 7` (TAMPER7) | `&gpio5 8` (TAMPER8) | ✅ Working |

### Root Cause
The decompiled DTB's phandle values (e.g., `0x16`, `0x08`) are **dynamically assigned by DTC** and unreliable. The correct values came from RightPoint Atom's original `.dts` source file found in the old Ubuntu 20.04 WSL project:

```
fec1: phy-reset-gpios = <&gpio5 7 GPIO_ACTIVE_LOW>;
fec2: phy-reset-gpios = <&gpio5 8 GPIO_ACTIVE_LOW>;
```

### Solution
Always refer to the **original `.dts` source** for correct pin assignments, not decompiled DTBs.

## 6. Boot Automation

### Done
Wanted to avoid manually setting `fdt_file` at every boot.

### Problem
`bootcmd` starts with `run findfdt`. It checks:
```bash
if test $board_name = EVK && test $board_rev = 14X14; then
    setenv fdt_file imx6ull-14x14-evk.dtb;
fi;
```
But this board is `ALPHA|MINI`, not `EVK`. The condition never matches, `fdt_file` stays undefined, and u-boot loads a random DTB.

### Solution
Modify `bootcmd` to force `fdt_file` before `run findfdt`:

```bash
setenv bootcmd 'setenv fdt_file imx6ull-atk.dtb; run findfdt; ...(rest unchanged)...'
saveenv
```

When `findfdt` checks `if test $fdt_file = undefined`, the variable is already set, so it skips.

## 7. Key Lessons Learned

1. **Decompiled DTBs are unreliable** — phandle values are DTC-dynamic. Find the original `.dts`.
2. **`phy-reset-gpios` is a generic property** — specified in DTS, no kernel driver modification needed.
3. **COM7 is unsuitable for large files** — 7.7MB doesn't transfer reliably. Use USB or network.
4. **Buildroot 2024.02 legacy config** — differs significantly from older versions. Use `savedefconfig`.
5. **NXP EVK DTS uses `phy-supply`**, RightPoint Atom uses `phy-reset-gpios` — two different PHY reset mechanisms.
6. **Check board model before relying on `findfdt`** — ALPHA board != EVK board, condition logic differs.
