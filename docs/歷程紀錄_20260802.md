# Day 7 — RGB LCD 顯示與 GT911 觸控螢幕（2026-08-02）

**目標：** 確認 ATK-MD0700R 7 吋 1024x600 RGB888 LCD 與 GT911 電容觸控的腳位連接（腳位對應），以 DRM/mxsfb 驅動 + PWM 背光點亮 LCD，並透過 I2C2 啟用 GT911 觸控螢幕——含完整除錯過程（核心設定、設備樹、GPIO 衝突）。

---

## 1. 腳位連接討論

動手改設備樹前，先依據底板原理圖逐一確認 LCD/觸控腳位。

### 1.1 LCD 連接器（40-Pin RGBLCD）

| 功能 | 信號 | i.MX6ULL Ball | IOMUX |
|:---|:---|:---|:---|
| RGB 資料 | LCD_DATA0–23 | （24 腳）| LCDIF_DATA00–23 |
| 像素時脈 | LCD_CLK | | LCDIF_CLK |
| 資料致能 | LCD_ENABLE | | LCDIF_ENABLE |
| 同步 | LCD_HSYNC / LCD_VSYNC | | LCDIF_HSYNC / LCDIF_VSYNC |
| 背光 PWM | BLT_PWM | N17 | GPIO1_IO08 / PWM1_OUT |
| 觸控 I2C | TSC_SCL / TSC_SDA | F17 / G13 | UART5_TXD/RXD = GPIO1_IO30/31（I2C2）|
| 觸控中斷 | CT_INT | M15 | GPIO1_IO09 |
| 觸控復位 | CT_RST | R6 | SNVS_TAMPER9 / GPIO5_IO09 |
| LCD 復位 | RESET（Pin 40）| — | **UM805RE POR IC 輸出**（不接 SoC）|

**硬體注意事項：**
- **SGM3157** 類比開關位於 `LCD_DATA7S/15S/23S`（與乙太網/NAND 匯流排共用）。這要求降低驅動能力：pinctrl 值用 **`0x49`** 取代原廠 `0x79`（手冊第 59 章對含 SGM3157 板子的建議）。
- **RESET（Pin 40）** 由 **UM805RE** 上電復位 IC 產生，SoC 沒有復位 GPIO → 省略 LCDIF reset pinctrl 條目。
- 背光 `BLT_PWM` → GPIO1_IO08 → **PWM1_OUT**。

### 1.2 面板時序（資料手冊第 59 章）

```
clock-frequency = 51200000;   /* 51.2 MHz */
hactive = 1024;  vactive = 600;
hfront-porch = 160; hback-porch = 140; hsync-len = 20;
vback-porch  = 20;  vfront-porch  = 12;  vsync-len   = 3;
hsync-active = 0; vsync-active = 0; de-active = 1; pixelclk-active = 0;
bits-per-pixel = 24; bus-width = 24;    /* RGB888 */
```

## 2. LCD 驅動實現

### 2.1 核心設定（`linux-imx/lcd.fragment`）

```kconfig
CONFIG_DRM=y
CONFIG_DRM_MXSFB=y
CONFIG_DRM_PANEL_SIMPLE=y
CONFIG_FB_CORE=y
CONFIG_FB=y
CONFIG_FB_DEVICE=y
CONFIG_DRM_FBDEV_EMULATION=y
CONFIG_PWM=y
CONFIG_PWM_IMX27=y
CONFIG_BACKLIGHT_CLASS_DEVICE=y
CONFIG_BACKLIGHT_PWM=y
CONFIG_LOGO=y
CONFIG_LOGO_LINUX_MONO=y
CONFIG_LOGO_LINUX_VGA16=y
CONFIG_LOGO_LINUX_CLUT224=y
```

以 `scripts/kconfig/merge_config.sh -m -O . .config audio.fragment lcd.fragment` 合併。

**重要坑——`CONFIG_FB_DEVICE`：** 核心 6.6 的 fbdev 框架已拆分；`fb_chrdev.o`（/dev/fbX）、`fb_procfs.o`（/proc/fb）、`fbsysfs.o`（/sys/class/graphics/fbX）**全部只在 `CONFIG_FB_DEVICE` 下編譯**（`drivers/video/fbdev/core/Makefile`）。DRM FBDEV 模擬層**不會自動 select 它**——只開 `CONFIG_FB=y` 時 mxsfb DRM 會註冊 fb0（dmesg 看得到），但沒有任何裝置節點。

### 2.2 設備樹（`imx6ull-atk.dts`）

**必須使用 graph 結構**——NXP 6.6 的 mxsfb 驅動（`mxsfb_drv.c`）**忽略 `display` 屬性**，呼叫 `drm_of_find_panel_or_bridge()` 需要 graph port + remote panel：

```dts
&lcdif {
	pinctrl-names = "default";
	pinctrl-0 = <&pinctrl_lcdif_dat_atk
		     &pinctrl_lcdif_ctrl_atk>;
	status = "okay";

	port {
		lcdif_out: endpoint {
			remote-endpoint = <&panel_in>;
		};
	};
};

panel_dpi: panel-dpi {
	compatible = "panel-dpi";
	width-mm = <154>;
	height-mm = <86>;

	panel-timing {
		clock-frequency = <51200000>;
		/* ...1.2 節時序... */
	};

	port {
		panel_in: endpoint {
			remote-endpoint = <&lcdif_out>;
		};
	};
};
```

- `panel-dpi` 通用 binding 由 **panel-simple** 處理（`CONFIG_DRM_PANEL_SIMPLE=y`，需要 `panel-timing` 節點）。
- pinctrl 群組：`pinctrl_lcdif_dat_atk`（24 支資料腳）與 `pinctrl_lcdif_ctrl_atk`（CLK/ENABLE/HSYNC/VSYNC）全部 **`0x49`**；`pinctrl_pwm1` = `MX6UL_PAD_GPIO1_IO08__PWM1_OUT 0x110b0`。
- NXP dtsi 已內建 **`backlight-display`** 節點：`compatible = "pwm-backlight"`、`pwms = <&pwm1 0 5000000>`（200Hz）、`brightness-levels = <0 4 8 16 32 64 128 255>`、`default-brightness-level = <6>`——與手冊範例完全一致 → 不另加背光節點。
- `&pwm1`：pinctrl + `status = "okay"`。

### 2.3 驗證

```
$ dmesg | grep -i -e mxsfb -e panel
```

## 3. GT911 觸控螢幕

### 3.1 I2C 位址探測

GT911 依復位時 INT 腳電平可能位於 `0x5d` 或 `0x14`。與其猜測，先掃匯流排：

```
$ i2cdetect -y -r 1          # i2c-1 = 21a4000.i2c = I2C2
00:          -- -- -- -- -- -- -- -- -- -- -- -- -- 
10: -- -- -- -- 14 -- -- -- -- -- -- -- -- -- -- -- 
→ GT911 在 0x14 有回應
```

### 3.2 設備樹（`&i2c2`）

```dts
&i2c2 {
	gt911: gt911@14 {
		compatible = "goodix,gt911";
		reg = <0x14>;
		pinctrl-names = "default";
		pinctrl-0 = <&pinctrl_tsc
			     &pinctrl_tsc_reset>;
		interrupt-parent = <&gpio1>;
		interrupts = <9 IRQ_TYPE_EDGE_FALLING>;
		reset-gpios = <&gpio5 9 GPIO_ACTIVE_LOW>;
		edge-failling-trigger;
		touchscreen-size-x = <1024>;
		touchscreen-size-y = <600>;
		status = "okay";
	};
};
```

- `pinctrl_tsc`（iomuxc）：`MX6UL_PAD_GPIO1_IO09__GPIO1_IO09 0x1b0b0`。
- `pinctrl_tsc_reset`（iomuxc_snvs）：`MX6ULL_PAD_SNVS_TAMPER9__GPIO5_IO09 0x17059`。

## 4. 除錯過程

| 問題 | 根因 | 解法 |
|-------|-----------|-----|
| 編了新內核但開機還是舊的 | U-Boot 從 **eMMC p1**（`/run/media/mmcblk1p1`）載入 zImage/dtb，不是隨身碟 | 把新 zImage/dtb 複製進 eMMC FAT 分割區（隨身碟檔案其實是對的）|
| `mxsfb: error -ENODEV: Cannot connect bridge` | NXP 6.6 mxsfb 用 `drm_of_find_panel_or_bridge()` → 需要 **graph port + remote panel**；傳統 `display` 屬性 + `display-timings` 被忽略 | 加 `&lcdif` port endpoint + `panel-dpi` 節點（含 `panel-timing`）；開 `CONFIG_DRM_PANEL_SIMPLE` |
| `display0/timing0: duplicate label` | 原廠 dtsi 在 `&lcdif` 內已有 `display0: display@0` | 刪掉 root 節點；在 `&lcdif` 內覆寫時序（同標籤自動合併）|
| 兩個 `pwm-backlight` 裝置 | NXP dtsi 已有 `backlight-display` | 移除重複的 root `backlight` 節點 |
| dmesg 顯示 fb0 註冊但無 `/dev/fb0`、`/proc/fb`、sysfs fb0 | 核心 6.6：`/dev/fbX`+`/proc/fb`+sysfs 藏在 **`CONFIG_FB_DEVICE`** 後面，`CONFIG_FB=y` 不會自動選 | 加 `CONFIG_FB_DEVICE=y` |
| `Goodix-TS: error -EBUSY: Failed to get irq GPIO` | `interrupts` 屬性會把 GPIO 鎖成 IRQ（gpiochip lock）；並存的 `irq-gpios` 再請求 → `gpiod_request → -EBUSY` | 移除 `irq-gpios`，只留 `interrupts`（驅動經 `client->irq` 請求中斷）|
| `pin MX6UL_PAD_GPIO1_IO09 already requested by 2040000.tsc; cannot claim for 2190000.mmc` | 原廠 EVK `pinctrl_usdhc1` 把 GPIO1_IO09 當 **SD1 RESET**——與 CT_INT 同腳 | 覆寫 `&usdhc1` 用不含 GPIO1_IO09 的新 `pinctrl_usdhc1_atk` |

## 5. 部署流程（改進）

不再需要隨身碟往返：

1. 在 Hermes（WSL）編譯：`make zImage`、`make dtbs`。
2. 把板子 SSH 金鑰複製到 Hermes（`/root/.ssh/atk_rsa_key`），並把公鑰寫入板子 `authorized_keys`（一次性，透過串口）。
3. `scp -i /root/.ssh/atk_rsa_key zImage imx6ull-atk.dtb root@192.168.1.100:/root/`
4. 板子上（串口 console）：複製到 `/run/media/mmcblk1p1/` + `sync`。
5. 斷電重開（reboot 不可靠）再驗證。

## 6. 重點總結

1. **NXP 6.6 mxsfb 只有 DRM 版本**：需要 graph（port → remote）連 panel 節點；傳統 `display` 屬性在那裡是死碼。
2. **核心 6.6 必須 `CONFIG_FB_DEVICE=y`** 才有 `/dev/fb0`、`/proc/fb` 與 sysfs fb 節點（DRM fbdev 模擬層不會自動選）。
3. 含 **SGM3157** 開關的板子，LCD 資料/控制腳 pinctrl **必須 0x49**（降低驅動能力、避免干擾匯流排）。
4. **本板 GT911 位址 = 0x14**——寫 DTS 前一律先 `i2cdetect`，不要預設 `0x5d`。
5. goodix 驅動在此內核**不要同時給 `interrupts` + `irq-gpios`**（同一個 GPIO）：IRQ 鎖定會讓 GPIO 請求回 -EBUSY。
6. **檢查每個 GPIO 是否有第二個使用者**：原廠 EVK usdhc1 的 SD1-RESET 腳（GPIO1_IO09）與 CT_INT 衝突；自訂 pinctrl 群組解決。
7. 用 **scp（Hermes → 板子）+ eMMC FAT 複製**部署比隨身碟流程更快更可靠。
