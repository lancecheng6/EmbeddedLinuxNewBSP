# ATK-IMX6U 新 BSP 建置歷程

> 日期：2026/07/27
> 從 NXP Yocto BSP 到最小嵌入式 Linux 系統的完整紀實

---

## 1. 下載 NXP BSP 並探索

### 做了什麼
下載 `LF_v6.18.2-1.0.0_images_IMX6UL7D.zip`，解壓後發現內容包含：
- `zImage` (10MB) — 預編譯核心
- `u-boot-imx6ull*.imx` — 多種 U-Boot binary
- `*.dtb` — 多種 Device Tree
- `*.uuu` — MfgTool 燒錄腳本

### 遇到的問題
這是 Yocto 預編譯映像，只有二進位檔，**沒有原始碼**。無法用 Buildroot 客製化。

### 解決方式
放棄直接使用 BSP 映像，改為從原始碼建置：
1. `git clone` Buildroot 2024.02
2. `git clone` NXP Linux kernel `lf-6.6.y`
3. `git clone` NXP U-Boot `lf_v2023.04`

---

## 2. Buildroot 環境建置

### 做了什麼
建立目錄結構，從基板備份 DTBs、zImage、rootfs 等資料到 `board_backup/`。

### 遇到的問題
**BR2_LEGACY 錯誤**
自訂的 `atk_imx6u_min_defconfig` 碰到 Buildroot 2024.02 的 legacy config 檢查失敗。原因是 `BR2_KERNEL_HEADERS_AS_KERNEL` 在 2024.02 中被移除。

### 解決方式
改用 `freescale_imx6ullevk_defconfig` 為基底，只做最小變更：
- 關閉核心編譯（手動管理）
- 關閉 U-Boot 編譯（手動管理）
- 設定 kernel headers 為 6.6 版
- 工具鏈成功編譯（GCC 12.3.0）
- Rootfs 成功產出（BusyBox，15MB）

---

## 3. 核心最小化配置

### 做了什麼
建立 `kernel-minimal.fragment`，用意是保留 UART、eMMC、FEC，關閉 DRM、USB、SOUND、GPU、WDT 等。

### 遇到的問題
`kernel-minimal.fragment` 中錯誤地寫了 `# CONFIG_NET is not set`，導致核心編譯後無網路支援。第一次開機時 `ifconfig: socket: Function not implemented`。

### 解決方式
改用 `savedefconfig` 流程：
1. `make imx_v6_v7_defconfig`
2. 手動關閉不需要的選項
3. `make savedefconfig` → 產出最小 diff defconfig
4. 儲存為 `kernel_atk_imx6u_defconfig_final`

---

## 4. 部署到板子

### 做了什麼
編譯 U-Boot、核心、DTB 後，要把檔案放到 boot 分割區（mmcblk1p1）。

### 遇到的問題

#### 4.1 SSH host key 衝突
Windows OpenSSH 不支援 `ssh-rsa` 演算法（預設關閉），板子的 dropbear 只提供 RSA key。
**解決：** `ssh -o HostKeyAlgorithms=+ssh-rsa`

#### 4.2 SSH 密碼認證失敗
Buildroot rootfs 覆蓋了 `/etc/shadow`，板子密碼被改為空白，但 dropbear 不允許空白密碼登入。
**解決：** COM7 登入後執行 `passwd` 設定新密碼，或使用 `sshpass -p ''`。

#### 4.3 COM7 傳大檔失敗
嘗試透過 COM7 以 base64 傳輸 7.7MB 的 zImage，但 shell heredoc 被終端機干擾、echo 指令行長度限制、printf 引號問題等，檔案一直損毀。
**解決：** 改用 USB 隨身碟 + u-boot 的 `fatload`/`fatwrite` 指令。

#### 4.4 COM7 傳輸特殊字元
即使 36KB 的 DTB 也傳不完整（base64 轉換有問題）。
**解決：** 改用 SSH + SCP（網路暢通後就很快了）。

## 5. PHY Reset 偵錯

### 做了什麼
設定 FEC 的 `phy-reset-gpios` 來控制 PHY Reset 腳位。

### 遇到的問題（重複猜錯三次）

| 版本 | fec1 reset | fec2 reset | 結局 |
|------|-----------|-----------|------|
| **猜錯 1** | `&gpio5 1` | — | PHY 不通 |
| **猜錯 2** | `&gpio5 8` | — | PHY 不通 |
| **猜錯 3** | `&gpio5 7`（跟 fec2 搞反） | `&gpio5 8` | PHY 不通 |
| **原始 DTS** | `&gpio5 7`（TAMPER7） | `&gpio5 8`（TAMPER8） | ✅ |

### 解決方式
在 **Ubuntu 20.04 WSL**（舊專案）中找到正點原子原始 DTS：`imx6ull-alientek-emmc.dts`，裡面明確寫了：

```
fec1: phy-reset-gpios = <&gpio5 7 GPIO_ACTIVE_LOW>;
fec2: phy-reset-gpios = <&gpio5 8 GPIO_ACTIVE_LOW>;
```

反編譯的 DTB 中 phandle 值（`0x16`、`0x08`）是 DTC 動態分配的，不可靠。應以原始 `.dts` 為準。

## 6. 開機自動化

### 做了什麼
希望開機後不需手動設 `fdt_file`。

### 遇到的問題
`bootcmd` 第一行是 `run findfdt`，它只在 `fdt_file = undefined` 時才執行。但重啟後 `fdt_file` 被還原了。

**root cause：** `findfdt` 的條件是：
```bash
if test $board_name = EVK && test $board_rev = 14X14; then
    setenv fdt_file imx6ull-14x14-evk.dtb;
fi;
```
但這塊板子是 `ALPHA|MINI`，不是 `EVK`，所以條件永遠不成立。`fdt_file` 永遠是 undefined，u-boot 就亂載入一個 DTB。

### 解決方式
修改 `bootcmd`，在 `run findfdt` 前先強制設 `fdt_file`：

```bash
setenv bootcmd 'setenv fdt_file imx6ull-atk.dtb; run findfdt; ...（其餘不變）...'
saveenv
```

這樣 `findfdt` 檢查 `fdt_file = undefined` 時，已經有值了，就會跳過。

## 7. 關鍵教訓

1. **反編譯的 DTB 不可靠** — phandle 值是 DTC 動態分配的，應找原始 `.dts` 檔
2. **`phy-reset-gpios` 是通用屬性** — 由 DTS 指定 GPIO，不需修改核心驅動
3. **COM7 不適合傳大檔** — 7.7MB 的 zImage 傳不成功，USB 或網路才是正解
4. **Buildroot 2024.02 的 legacy config** — 與舊版差異大，用 `savedefconfig` 最穩
5. **NXP EVK DTS 用 `phy-supply`**，正點原子用 `phy-reset-gpios` — 兩種不同的 PHY reset 機制
6. **先確認板子型號再參考 `findfdt`** — ALPHA 板不等於 EVK，條件判斷不同

## 8. 最終成果

|------|------|------|
| **Buildroot** | `buildroot/` | 2024.02，GCC 12.3.0 |
| **核心原始碼** | `linux-imx/` | NXP lf-6.6.y |
| **核心 defconfig** | `configs/kernel_defconfig/kernel_atk_imx6u_defconfig_final` | 最小化配置 |
| **U-Boot 原始碼** | `uboot-imx/` | NXP lf_v2023.04 |
| **Device Tree** | `DTS/imx6ull-atk.dts` | 自訂 DTS |
| **Rootfs** | `buildroot/output/images/rootfs.tar` | BusyBox 最小系統 |
| **部署核心** | `/boot/zImage` (板子) | 7.7MB，含網路 |
| **部署 DTB** | `/boot/imx6ull-atk.dtb` (板子) | 36KB |
| **PHY reset** | GPIO5_IO07 (fec1), GPIO5_IO08 (fec2) | SR8201F |
