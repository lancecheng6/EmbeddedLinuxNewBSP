**Documents Reference:**
- TPT8485E: `Datasheet_TP8485E.pdf` (3Peak, Rev. CA20241219E3)
- i.MX6ULL: `IMX6ULLIEC.pdf` (Rev. 1.2, 11/2017)

## 1. i.MX6ULL UART3 Ball Assignments (14×14 mm MAPBGA)

| Signal Name | Ball (14×14) | Power Group | Default Mode | Note |
|---|---|---|---|---|
| UART3_TX_DATA | H17 | NVCC_UART | ALT5 (GPIO) | UART3 transmit data |
| UART3_RX_DATA | H16 | NVCC_UART | ALT5 (GPIO) | UART3 receive data |

> **Note:** UART3 default mode is ALT5 (GPIO) at reset. IOMUX must be configured to UART3 DCE mode before use.

### Conflict with UART2 RTS/CTS

The same balls (H16, H17) are also claimed by UART2's hardware flow control in the default `imx6ul-14x14-evk.dtsi`:

| Ball | UART2 Function | UART3 Function |
|---|---|---|
| H17 | UART2_CTS (output) | **UART3_TXD** |
| H16 | UART2_RTS (input) | **UART3_RXD** |

This conflict must be resolved in the Device Tree before UART3 can be used.

## 2. TP8485E SOP-8 Pin Assignments

### 2.1 Pin Table

| Pin | Name | I/O | Type | Description |
|:---:|:---:|:---:|:---:|---|
| 1 | **RO** | O | Digital | Receiver Output. TTL/CMOS level, connects to SoC UART RX |
| 2 | **RE** | I | Digital | Receiver Enable. Active Low. Connect to DE for half-duplex control |
| 3 | **DE** | I | Digital | Driver Enable. Active High. Connect to RE for half-duplex control |
| 4 | **DI** | I | Digital | Driver Input. TTL/CMOS level, connects to SoC UART TX |
| 5 | GND | — | Power | Ground |
| 6 | **A** | IO | Bus | Non-inverting RS-485 bus pin |
| 7 | **B** | IO | Bus | Inverting RS-485 bus pin |
| 8 | VCC | — | Power | 3.0V ~ 5.5V supply |

### 2.2 Functional Table

| RE | DE | DI | Bus (A-B) | RO |
|:--:|:--:|:--:|:--------:|:--:|
| L | L | X | Z (High-Z) | **H** (Fail-Safe) |
| L | L | X | Z | **H** |
| L | L | X | Z | **H** |
| H | L | X | Z | **L** |
| X | H | L | A < B | H |
| X | H | H | A > B | L |

> **Key Feature:** Full Fail-Safe — RO outputs High when bus is open, shorted, or terminated but undriven.

### 2.3 Package (Top View)

```
       ┌──────────┐
    1  │ RO   VCC │ 8
    2  │ RE    B  │ 7
    3  │ DE    A  │ 6
    4  │ DI   GND │ 5
       └──────────┘
```

## 3. Hardware Interface Design

### 3.1 SoC UART3 ↔ TP8485E Connection Table

| i.MX6ULL Signal | Ball (14×14) | I/O | → | TP8485E Pin | Pin Name | Description |
|---|---|---|---|---|---|---|
| UART3_TX_DATA | H17 | → output | → | 4 | DI | Driver input (SoC → RS-485) |
| UART3_RX_DATA | H16 | ← input | ← | 1 | RO | Receiver output (RS-485 → SoC) |

### 3.2 Half-Duplex Auto Direction Control

The board uses an **inverter** circuit to automatically control RS-485 direction:

```
SoC UART3_TXD ──→ INVERTER ──→ RE (Pin 2)
                   │           │
                   │           DE (Pin 3)
                   │           │
                   │     [RE and DE shorted together]
                   │
                   └─────────→ DI (Pin 4)
```

**Operation:**

| TXD State | Inverted | RE | DE | Mode |
|-----------|----------|:--:|:--:|------|
| High (idle) | Low | **0** | **0** | **Receive** (driver disabled) |
| Low (start bit) | High | **1** | **1** | **Transmit** (receiver disabled) |

- **Idle state:** TXD = High → Inverter output Low → RE=0, DE=0 → RS-485 bus is in receive mode
- **Transmitting:** Start bit (Low) triggers RE/DE → automatically switches to transmit mode
- No extra GPIO needed for direction control

### 3.3 RS-485 Bus Connections

| TP8485E Pin | Signal | To |
|:---:|:---|---|
| 6 | A | RS-485 differential pair + |
| 7 | B | RS-485 differential pair − |
| 5 | GND | Ground |
| 8 | VCC | 3.3V supply |

### 3.4 Typical Application Circuit

```
SoC                                  TP8485E
┌───────┐                          ┌──────────┐
│       │                          │          │
│ H17   │──UART3_TXD──→ INVERTER ──│ DI (4)   │
│ TX    │              └──────┬────│ RE (2)   │
│       │                     │    │ DE (3)   │
│ H16   │──UART3_RXD──────────│────│ RO (1)   │
│ RX    │                     │    │          │
│       │                     │    │ A (6) ───┤ RS-485 A (+)
│       │                     │    │ B (7) ───┤ RS-485 B (−)
│       │                     │    │          │
│       │                     │    │ VCC (8) ─┤ 3.3V
│       │                     │    │ GND (5) ─┤ GND
└───────┘                     └──────────┘
```

## 4. Device Tree Configuration

### 4.1 Pin Conflict Resolution

The `imx6ul-14x14-evk.dtsi` defines UART2's pinctrl with RTS/CTS on the same balls as UART3:

```dts
/* dtsi — pinctrl_uart2 claims H16/H17 as UART2 RTS/CTS */
pinctrl_uart2: uart2grp {
    fsl,pins = <
        MX6UL_PAD_UART2_TX_DATA__UART2_DCE_TX     0x1b0b1
        MX6UL_PAD_UART2_RX_DATA__UART2_DCE_RX     0x1b0b1
        MX6UL_PAD_UART3_RX_DATA__UART2_DCE_RTS    0x1b0b1  /* ← conflicts */
        MX6UL_PAD_UART3_TX_DATA__UART2_DCE_CTS    0x1b0b1  /* ← conflicts */
    >;
};
```

To free these pins, the DTS **overrides** `pinctrl_uart2` to remove the RTS/CTS entries, and **deletes** the `uart-has-rtscts` property from `&uart2`.

### 4.2 DTS Changes (imx6ull-atk.dts)

```dts
/* UART2: Remove RTS/CTS to free pins for UART3 */
&uart2 {
    /delete-property/ uart-has-rtscts;
};

/* UART3: Enable with TP8485E RS-485 */
&uart3 {
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_uart3>;
    /delete-property/ dmas;
    /delete-property/ dma-names;
    status = "okay";
};
```

### 4.3 IOMUX Pinctrl Override

```dts
/* IOMUX: UART2 (RTS/CTS removed) + UART3 pinctrl */
&iomuxc {
    pinctrl_uart2: uart2grp {
        fsl,pins = <
            MX6UL_PAD_UART2_TX_DATA__UART2_DCE_TX  0x1b0b1
            MX6UL_PAD_UART2_RX_DATA__UART2_DCE_RX  0x1b0b1
        >;
    };

    pinctrl_uart3: uart3grp {
        fsl,pins = <
            MX6UL_PAD_UART3_TX_DATA__UART3_DCE_TX  0x1b0b1
            MX6UL_PAD_UART3_RX_DATA__UART3_DCE_RX  0x1b0b1
        >;
    };
};
```

> **Note on `/delete-property/`:** DTS properties can be overridden by redefining with the same name, or deleted using `/delete-property/ <name>;`. Node labels (e.g., `pinctrl_uart2: uart2grp`) are fully replaced when redefined in a DTS file.

### 4.4 DMA Configuration

UART3's DMA channels are removed to avoid deferred probe (SDMA driver is built as module):

```dts
/delete-property/ dmas;
/delete-property/ dma-names;
```

This forces UART3 to use PIO (interrupt-driven) mode instead of DMA.

## 5. DTB Deployment Notes

### 5.1 Issue: FAT Write Cache

Initial attempts to deploy the DTB via `scp` → `sync` → `reboot` resulted in incomplete writes. The FAT32 filesystem on the boot partition (mmcblk1p1) did not reliably flush write caches before the `reboot` command.

### 5.2 Reliable Deploy Procedure

```
1. scp imx6ull-atk.dtb root@board:/boot/
2. ssh root@board "sync; sync"
3. Wait 5 seconds
4. Manually power cycle the board (do not use "reboot")
```
