# Day 8 — SystemUI Development: Buildroot Qt5, systemui Build & Display Debug (2026-08-03)

**Objective:** Bring up the factory SystemUI (Qt5 QML desktop) on our custom
buildroot rootfs: build the Qt5 cross toolchain environment, port and compile
the systemui source (originally Qt 5.6-era), deploy it with auto-start, and
fix the display noise/jitter problems down to the LCD signal level.

- Deployment: `systemui` binary → `/opt/ui/systemui`; apps →

The buildroot Qt5 package set was derived from **both** dependency layers:

| Layer | Source | Example |

## 3. Rootfs Deploy Accident & U-Boot Rescue

### 3.1 The Accident

Deploying rootfs v1 with `mount /dev/mmcblk1p2 /mnt; rm -rf /mnt/*` while the
board was running its own rootfs **deleted `/bin/login` and busybox** → board
bricked (Kernel panic: no working init).

### 3.2 Rescue Path

1. U-Boot rescue boot `init=/bin/sh` failed (busybox itself was deleted).
2. Solution: buildroot `BR2_TARGET_ROOTFS_EXT2` → produce **rootfs.ext2**
   image → copy to USB stick → U-Boot:
   ```
   usb start
   fatload usb 0:1 0x81000000 rootfs.ext2
   mmc write 0x81000000 0x45000 0x40000   # p2 starts at sector 282624 = 0x45000
   boot
   ```
3. **Critical trap:** `mmc write ... 282624` — U-Boot parses numbers as
   **hexadecimal**, so `282624` became decimal 2631204 and the image was
   written to the wrong block. Correct form is `0x45000`.

### 3.3 SSH Maintenance after re-flash

- `authorized_keys` was replaced (factory ed25519 key ≠ our ssh-rsa key).
- dropbear host key changed → `ssh-keygen -R 192.168.1.100`.
- Board has no sftp-server → use **`scp -O`** (legacy protocol).

## 7. Display Noise Debug (the core chapter)

**Symptom:** colored dots (white/yellow) on image lines + text jittering
horizontally.

### 7.1 Test sequence (systematic exclusion)

| Test | Result | Conclusion |
|------|--------|-----------|
| Solid red → fb0 | clean | LCD/fb fine |
| BMP pixel analysis (isolated/yellow dots) | clean | image fine |
| Checkerboard 8px (high-contrast edges) | clean | timing sampling OK at block level |
| **fb0 screenshot captured → viewed on PC** | **clean** | **Qt rendering chain 100% fine** |

→ Since the framebuffer content is perfect but the physical screen shows
dots, the corruption happens **between eLCDIF and the LCD driver IC**:
signal-integrity / PCLK sampling edge issues during rapid data transitions
(crosstalk, ground bounce, slew).

### 7.2 Fixes

| Attempt | Change | Result |
|---------|--------|--------|
| 1. Invert PCLK sampling edge | `pixelclk-active = <0>` → `<1>` | ~50% improvement; **jitter gone** |
| 2. Stronger pad drive + SRE | LCDIF dat/ctrl pinctrl `0x49` → `0x1b0b0` | **fully clean** ✅ |

Note: `0x49` was the manual's SGM3157-recommended low drive; with
`pixelclk-active=<1>` the sampling phase avoids the unstable transition
zone, and `0x1b0b0` (faster slew, stronger drive) sharpens the edges further.

## 8. App Deployment & PNG/JPEG Enablement

### 8.1 Building led + clock Apps

Only these two apps were built (per plan). Both compiled **first-try with zero
errors** using the buildroot cross qmake:

```
cd led/ && output/host/bin/qmake led.pro && make -j8    # → led
cd clock/ && output/host/bin/qmake clock.pro && make -j8 # → clock
```

- Both use `client.pri` (`QT += remoteobjects` + `REPC_REPLICA`) — already
  available.
- `QMAKE_POST_LINK` auto-copied the binaries to `ui/src/apps/`.
- Deployment: binaries → `/opt/ui/src/apps/`; icons (appicons/*.png);
  config via cfg files (page1 = LED, page2 = clock).
- Launch mechanism verified: systemui executes
  `/opt/ui/src/apps/<programName>` (from cfg column 3).

### 8.2 Dock Configuration

`apk3.cfg` controls the bottom Dock (BottomApp reads it at startup):

```
appicons/led.png LED led
appicons/clock.png 时钟 clock
```

Dock shows both icons; tapping launches the app (same launch path as the
pages). Swipe left/right switches page 1 ↔ page 2 with the Dock intact.

### 8.3 Black-corner Icon Problem

After converting icons to BMP (no alpha), the rounded-corner icons showed
**four black right-angle corners** — BMP has no alpha channel, so the
transparent area rendered black.

### 8.4 PNG/JPEG Enablement (the proper fix)

Added to the buildroot fragment:

```
BR2_PACKAGE_QT5BASE_PNG=y
BR2_PACKAGE_QT5BASE_JPEG=y
```

Findings during the rebuild:
- **PNG is built INTO QtGui** (qpnghandler, not a plugin) — no `libqpng.so`
  exists; once configured it just works.
- **JPEG is a plugin** (`libqjpeg.so` in `plugins/imageformats/`).
- **Adding a dependency does NOT automatically re-configure qt5base** —
  `make qt5base-dirclean` was required before the new options took effect.
- Rebuilt rootfs (v3), re-flashed via the USB-stick + `mmc write` flow.
- Reverted cfg icons to the original `.png` — rounded corners now transparent,
  background image could also return to jpg if desired.

### 8.5 Fonts into the Overlay

Fonts (DejaVuSans + wqy-zenhei) were added to
`rootfs-overlay/usr/lib/fonts/` so every future rootfs build includes them
(no more manual scp after re-flash).

### 8.6 Touch Interaction Verification (verify round 2)

- Swipe left/right: page 1 (LED) ↔ page 2 (clock) — smooth.
- Tapping LED icon: LED control UI opens ("电筒关").
- Tapping clock icon: clock UI shows current time.
- Tapping Dock icons: apps launch correctly.

## 10. Key Takeaways

1. **U-Boot numbers are hex** — always write `mmc write` block addresses in
   hex (`0x45000`), not decimal.
2. **Never deploy over a running rootfs** — boot a rescue system first
   (ext2 image via USB + `mmc write` is the reliable path).
3. **Buildroot Qt5 needs C++ toolchain** — `BR2_TOOLCHAIN_BUILDROOT_CXX=y`
   plus a forced gcc-final rebuild.
4. **Qt 5.15 has no GL here** — graphicaleffects is unavailable; remove
   unneeded imports/effects instead of enabling GL.
5. **Framebuffer screenshot debugging** — dump fb0, convert to BMP, and
   view on PC to separate software rendering from hardware/signal issues.
6. **Display noise on i.MX6ULL RGB888** — try `pixelclk-active` inversion
   first, then stronger pinctrl (`0x1b0b0`); keep the manual's SGM3157
   drive-strength note in mind.
7. **`scp -O`** for dropbear boards without sftp-server; refresh
   `authorized_keys` and host keys after every rootfs re-flash.
8. **Qt 5.15 PNG is built into QtGui** (no plugin) while **JPEG is a
   plugin** (`libqjpeg.so`) — check the real mechanism before assuming.
9. **New qt5base options need `make qt5base-dirclean`** — adding a
   dependency does not trigger a re-configure.
10. **Rootfs re-flash wipes runtime changes** — fonts/keys/UI tweaks must
    live in the buildroot overlay, not just on the board.
