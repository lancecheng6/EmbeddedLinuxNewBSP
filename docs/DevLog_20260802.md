# Day 7 — RGB LCD Display & GT911 Touchscreen (2026-08-02)

**Objective:** Verify the ATK-MD0700R 7" 1024x600 RGB888 LCD + GT911
capacitive touch wiring (pin mapping), enable the LCD with the DRM/mxsfb
driver + PWM backlight, and enable the GT911 touchscreen over I2C2 —
including the full debug journey (kernel config, device tree, GPIO
conflicts).

---

## 1. Pin Mapping Discussion

The LCD/touch wiring was verified against the baseboard schematic before touching
the device tree.

### 1.1 LCD Connector (40-pin RGBLCD)

| Function | Signal | i.MX6ULL Ball | IOMUX |
|:---|:---|:---|:---|
| RGB data | LCD_DATA0–23 | (24 pins) | LCDIF_DATA00–23 |
| Pixel clock | LCD_CLK | | LCDIF_CLK |
| Data enable | LCD_ENABLE | | LCDIF_ENABLE |
| Sync | LCD_HSYNC / LCD_VSYNC | | LCDIF_HSYNC / LCDIF_VSYNC |
| Backlight PWM | BLT_PWM | N17 | GPIO1_IO08 / PWM1_OUT |
| Touch I2C | TSC_SCL / TSC_SDA | F17 / G13 | UART5_TXD/RXD = GPIO1_IO30/31 (I2C2) |
| Touch interrupt | CT_INT | M15 | GPIO1_IO09 |
| Touch reset | CT_RST | R6 | SNVS_TAMPER9 / GPIO5_IO09 |
| LCD reset | RESET (pin 40) | — | **UM805RE POR IC output** (not tied to SoC) |

**Hardware notes:**
- **SGM3157** analog switches sit on `LCD_DATA7S/15S/23S` (shared with the
  Ethernet/NAND bus). This forces a lower drive strength: pinctrl value
  **`0x49`** instead of the stock `0x79` (manual chapter 59 recommendation
  for boards with SGM3157).
- **RESET (pin 40)** is generated by a **UM805RE** power-on-reset IC, so no
  SoC reset GPIO exists — the LCDIF reset pinctrl entry is omitted.
- Backlight `BLT_PWM` → GPIO1_IO08 → **PWM1_OUT**.

### 1.2 Panel Timing (datasheet chapter 59)

```
clock-frequency = 51200000;   /* 51.2 MHz */
hactive = 1024;  vactive = 600;
hfront-porch = 160; hback-porch = 140; hsync-len = 20;
vback-porch  = 20;  vfront-porch  = 12;  vsync-len   = 3;
hsync-active = 0; vsync-active = 0; de-active = 1; pixelclk-active = 0;
bits-per-pixel = 24; bus-width = 24;    /* RGB888 */
```

## 2. LCD Driver Enablement

### 2.1 Kernel Config (`linux-imx/lcd.fragment`)

```kconfig
CONFIG_DRM=y
CONFIG_DRM_MXSFB=y
CONFIG_DRM_PANEL_SIMPLE=y
CONFIG_FB_CORE=y
CONFIG_FB=y
CONFIG_FB_DEVICE=y
CONFIG_DRM_FBDEV_EMULATION=y
CONFIG_PWM=y
CONFIG_PWM_IMX27=y
CONFIG_BACKLIGHT_CLASS_DEVICE=y
CONFIG_BACKLIGHT_PWM=y
CONFIG_LOGO=y
CONFIG_LOGO_LINUX_MONO=y
CONFIG_LOGO_LINUX_VGA16=y
CONFIG_LOGO_LINUX_CLUT224=y
```

Merged with `scripts/kconfig/merge_config.sh -m -O . .config audio.fragment lcd.fragment`.

**Key gotcha — `CONFIG_FB_DEVICE`:** in kernel 6.6 the fbdev framework was
split up; `fb_chrdev.o` (/dev/fbX), `fb_procfs.o` (/proc/fb) and `fbsysfs.o`
(/sys/class/graphics/fbX) are all compiled only under
**`CONFIG_FB_DEVICE`** (`drivers/video/fbdev/core/Makefile`). DRM FBDEV
emulation does *not* select it automatically — with only `CONFIG_FB=y` the
`mxsfb` DRM driver registers fb0 (dmesg shows it) but no device node exists.

### 2.2 Device Tree (`imx6ull-atk.dts`)

**Graph structure is mandatory** — the NXP 6.6 mxsfb driver
(`mxsfb_drv.c`) ignores the `display` property; it calls
`drm_of_find_panel_or_bridge()` which needs a graph port + remote panel:

```dts
&lcdif {
	pinctrl-names = "default";
	pinctrl-0 = <&pinctrl_lcdif_dat_atk
		     &pinctrl_lcdif_ctrl_atk>;
	status = "okay";

	port {
		lcdif_out: endpoint {
			remote-endpoint = <&panel_in>;
		};
	};
};

panel_dpi: panel-dpi {
	compatible = "panel-dpi";
	width-mm = <154>;
	height-mm = <86>;

	panel-timing {
		clock-frequency = <51200000>;
		/* ...timing from section 1.2... */
	};

	port {
		panel_in: endpoint {
			remote-endpoint = <&lcdif_out>;
		};
	};
};
```

- `panel-dpi` generic binding is handled by **panel-simple**
  (`CONFIG_DRM_PANEL_SIMPLE=y`, requires a `panel-timing` node).
- Pinctrl groups: `pinctrl_lcdif_dat_atk` (24 data pins) and
  `pinctrl_lcdif_ctrl_atk` (CLK/ENABLE/HSYNC/VSYNC) all with value **`0x49`**;
  `pinctrl_pwm1` = `MX6UL_PAD_GPIO1_IO08__PWM1_OUT 0x110b0`.
- The NXP dtsi already ships a **`backlight-display`** node with
  `compatible = "pwm-backlight"`, `pwms = <&pwm1 0 5000000>` (200 Hz),
  `brightness-levels = <0 4 8 16 32 64 128 255>` and
  `default-brightness-level = <6>` — identical to the manual's example, so no
  extra backlight node was added.
- `&pwm1`: pinctrl + `status = "okay"`.

### 2.3 Verification

```
$ dmesg | grep -i -e mxsfb -e panel

[ 1.69] [drm] Initialized mxsfb-drm 1.0.0 20160824 for 21c8000.lcdif on minor 0
```

## 3. GT911 Touchscreen

### 3.1 I2C Address Discovery

GT911 can live at `0x5d` or `0x14` depending on the INT line state at reset.
Rather than guessing, probe the bus first:

```
$ i2cdetect -y -r 1          # i2c-1 = 21a4000.i2c = I2C2
00:          -- -- -- -- -- -- -- -- -- -- -- -- -- 
10: -- -- -- -- 14 -- -- -- -- -- -- -- -- -- -- -- 
→ GT911 answered at 0x14
```

### 3.2 Device Tree (`&i2c2`)

```dts
&i2c2 {
	gt911: gt911@14 {
		compatible = "goodix,gt911";
		reg = <0x14>;
		pinctrl-names = "default";
		pinctrl-0 = <&pinctrl_tsc
			     &pinctrl_tsc_reset>;
		interrupt-parent = <&gpio1>;
		interrupts = <9 IRQ_TYPE_EDGE_FALLING>;
		reset-gpios = <&gpio5 9 GPIO_ACTIVE_LOW>;
		edge-failling-trigger;
		touchscreen-size-x = <1024>;
		touchscreen-size-y = <600>;
		status = "okay";
	};
};
```

- `pinctrl_tsc` (iomuxc): `MX6UL_PAD_GPIO1_IO09__GPIO1_IO09 0x1b0b0`.
- `pinctrl_tsc_reset` (iomuxc_snvs): `MX6ULL_PAD_SNVS_TAMPER9__GPIO5_IO09 0x17059`.

### 3.3 Verification


## 4. Debug Journey

| Issue | Root cause | Fix |
|-------|-----------|-----|
| New kernel built but old one booted | U-Boot loads zImage/dtb from **eMMC p1** (`/run/media/mmcblk1p1`), not from the USB stick | copy new zImage/dtb into the eMMC FAT partition (stick files were already correct) |
| `mxsfb: error -ENODEV: Cannot connect bridge` | NXP 6.6 mxsfb uses `drm_of_find_panel_or_bridge()` → needs a **graph port + remote panel**; the classic `display` property + `display-timings` is ignored | add `&lcdif` port endpoint + `panel-dpi` node with `panel-timing`; enable `CONFIG_DRM_PANEL_SIMPLE` |
| `display0/timing0: duplicate label` | stock dtsi already defines `display0: display@0` inside `&lcdif` | drop the root-level node; override the timing inside `&lcdif` (same label merges) |
| Two `pwm-backlight` devices | NXP dtsi already has `backlight-display` | remove the duplicate root `backlight` node |
| fb0 registered (dmesg) but no `/dev/fb0`, `/proc/fb`, sysfs fb0 | kernel 6.6: `/dev/fbX`+`/proc/fb`+sysfs live behind **`CONFIG_FB_DEVICE`**, not auto-selected by `CONFIG_FB=y` | add `CONFIG_FB_DEVICE=y` |
| `Goodix-TS: error -EBUSY: Failed to get irq GPIO` | `interrupts` property locks the GPIO as IRQ (gpiochip lock); a parallel `irq-gpios` then fails with `gpiod_request → -EBUSY` | drop `irq-gpios`, keep `interrupts` (driver requests IRQ via `client->irq`) |
| `pin MX6UL_PAD_GPIO1_IO09 already requested by 2040000.tsc; cannot claim for 2190000.mmc` | stock EVK `pinctrl_usdhc1` uses GPIO1_IO09 as **SD1 RESET** — same pin as CT_INT | override `&usdhc1` with a new `pinctrl_usdhc1_atk` without GPIO1_IO09 |

## 5. Deployment Flow (improved)

USB-stick round-trips are no longer needed:

1. Build on Hermes (WSL): `make zImage`, `make dtbs`.
2. Copy the board SSH key onto Hermes (`/root/.ssh/atk_rsa_key`) and the
   public key into the board's `authorized_keys` (once, via serial).
3. `scp -i /root/.ssh/atk_rsa_key zImage imx6ull-atk.dtb root@192.168.1.100:/root/`
4. On the board (serial console): copy over `/run/media/mmcblk1p1/` + `sync`.
5. Power-cycle (reboot is unreliable) and verify.

## 6. Key Takeaways

1. **NXP 6.6 mxsfb is DRM-only**: it needs a graph (port → remote) with a
   panel node; the legacy `display` property is dead code there.
2. **`CONFIG_FB_DEVICE=y`** is required for `/dev/fb0`, `/proc/fb` and
   sysfs fb nodes in kernel 6.6 (not selected by DRM fbdev emulation).
3. **pinctrl 0x49** for LCD data/ctrl pins is mandatory on boards with
   **SGM3157** switches (reduces drive strength, avoids bus interference).
4. **GT911 address = 0x14** on this board — always `i2cdetect` before writing
   the DTS instead of assuming `0x5d`.
5. **Do not combine `interrupts` + `irq-gpios`** on the same GPIO for the
   goodix driver in this kernel — the IRQ lock makes the GPIO request fail
   with -EBUSY.
6. **Check every GPIO for second users**: the stock EVK usdhc1 SD1-RESET pin
   (GPIO1_IO09) collided with CT_INT; a custom pinctrl group fixed it.
7. Deployment via **scp (Hermes → board) + eMMC FAT copy** is faster and more
   reliable than the USB-stick workflow.
