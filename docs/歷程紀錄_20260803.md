# Day 8 — SystemUI 開發：Buildroot Qt5、systemui 編譯與顯示除錯（2026-08-03）

**目標：** 在我們自建的 buildroot rootfs 上實現出廠 SystemUI（Qt5 QML 桌面）：建立 Qt5 交叉編譯環境、移植並編譯 systemui 原始碼（原為 Qt 5.6 時代）、部署並自動啟動，最後把顯示的噪點/抖動問題一路除錯到 LCD 訊號層。

---

## 1. 開發環境建立

### 1.1 原始碼

將整套出廠 `SourceCode` 資料夾（1.2 GB）從開發板資料包複製到 `EmbeddedLinuxNewBSP/`，並在 `09、Qt综合例程源码/` 內解壓 `systemui.tar.bz2`：

```
systemui/        主程式（QML + C++）
dashboard/ music/ player/ camera/ ...   23 個 App 專案
server/          SystemUICommonApiServer（Qt Remote Objects）
ui/              部署目錄（src/ + 編譯產物）
build.sh         一鍵編譯腳本（需出廠 Yocto Qt5 SDK）
```

### 1.2 使用說明研讀（PDF 重點）

- UI 為 **QML + C++**，出廠系統 runtime 為 Qt **5.12.9**；build.sh 用的 Yocto SDK `fsl-imx-x11 4.1.15-2.1.0` 內建 Qt **5.6**——意即原始碼是 Qt 5.6 時代的程式。
- 部署方式：`systemui` 可執行檔 → `/opt/ui/systemui`；App → `/opt/ui/src/apps/`；顯示哪些 App 由 `apk1~3.cfg` 控制。
- 顯示插件為 **Linuxfb**（無視窗管理，撕裂屬預期）。

### 1.3 規劃方法——套件清單來自兩層掃描

buildroot 的 Qt5 套件集由**兩層依賴**推導：

| 層級 | 來源 | 例子 |
|:---|:---|:---|
| 編譯期 | 各 `.pro` 的 `QT +=` | dashboard：`3d*` → qt53d |
| 執行期 | 各 `.qml` 的 `import` | `QtQuick.Controls 2.12` → qt5quickcontrols2 |

只編 systemui 的最小組合：**qt5base（+linuxfb）、qt5declarative(+quick)、qt5quickcontrols2、qt5remoteobjects**（server.pri 用了 `QT += remoteobjects`）+ `BR2_TOOLCHAIN_BUILDROOT_CXX=y`。

## 2. Buildroot Qt5 編譯

`qt5.fragment`（CXX + 4 套件）以 `support/kconfig/merge_config.sh` 合併（buildroot 的腳本路徑，不是 `scripts/kconfig/`）。

### 2.1 遇到的問題

| 問題 | 根因 | 解法 |
|-------|-----------|-----|
| 找不到 merge_config.sh | buildroot 放在 `support/kconfig/` | 改用正確路徑 |
| `qt5base: Cannot run target compiler ... g++` | 工具鏈是**純 C 版**；`BR2_TOOLCHAIN_BUILDROOT_CXX` 未開 → 沒有 g++ | 加 CXX 選項 + `make host-gcc-final-dirclean` 完整重編（約 30 分鐘）|
| `qt5graphicaleffects` 需要 OpenGL | i.MX6ULL 無 GPU | systemui 的 `import QtGraphicalEffects` 其實沒用到 → 刪 import + 不開套件 |

Rootfs v1 驗證：`libQt5*.so`（16 個庫）、`libqlinuxfb.so`、`/dev/fb0`、GT911 觸摸、網路、音訊全部正常。

## 3. Rootfs 部署事故與 U-Boot 救援

### 3.1 事故

在板子**運行自身 rootfs 時**用 `mount /dev/mmcblk1p2 /mnt; rm -rf /mnt/*` 部署 → **刪掉了 `/bin/login` 與 busybox** → 板子變磚（Kernel panic: no working init）。

### 3.2 救援路徑

1. U-Boot 救援引導 `init=/bin/sh` 失敗（busybox 也被刪了）。
2. 解決：buildroot 開 `BR2_TARGET_ROOTFS_EXT2` → 產出 **rootfs.ext2** 鏡像 → 複製到隨身碟 → U-Boot：
   ```
   usb start
   fatload usb 0:1 0x81000000 rootfs.ext2
   mmc write 0x81000000 0x45000 0x40000   # p2 起始 sector 282624 = 0x45000
   boot
   ```
3. **致命坑：** `mmc write ... 282624` —— U-Boot 把數字當**十六進位**，`282624` 變成十進位 2631204，鏡像寫到錯誤 block。正確寫法為 `0x45000`。

### 3.3 重燒後的 SSH 維護

- `authorized_keys` 被替換（出廠 ed25519 鑰匙 ≠ 我們的 ssh-rsa）。
- dropbear host key 變了 → `ssh-keygen -R 192.168.1.100`。
- 板子沒有 sftp-server → 改用 **`scp -O`**（舊版 SCP 協議）。

## 4. systemui 編譯與部署

### 4.1 交叉編譯

```
cd systemui/
output/host/bin/qmake systemui.pro
make -j8
```
只有 deprecated 警告（`QProcess::start(QString)`、`qrand()`），無錯誤。
`QMAKE_POST_LINK` 自動把二進位複製到 `ui/systemui`。

### 4.2 Rootfs v2（overlay）

- `ui/`（23 MB）→ `board/atk-imx6u/rootfs-overlay/opt/ui`
- `/etc/init.d/S99systemui` 啟動 `QT_QPA_PLATFORM=linuxfb ./systemui &`
- `apk1~3.cfg` 清空（尚未編任何 App）
- **缺庫：** systemui 啟動報 `libstdc++.so.6: cannot open shared object`——buildroot 的 gcc-final 安裝機制壞掉（缺 `.files-list`）→ 手動把工具鏈的 `libstdc++.so*` + `libatomic.so*` 複製進 overlay。

## 7. 顯示噪點除錯（核心章節）

**症狀：** 圖片人物線條出現白點/黃點 + 文字水平微微抖動。

### 7.1 測試流程（逐步排除）

| 測試 | 結果 | 結論 |
|------|--------|-----------|
| 純紅寫 fb0 | 乾淨 | LCD/fb 正常 |
| BMP 像素分析（孤立點/黃點）| 乾淨 | 圖片正常 |
| 8px 棋盤格（高對比邊緣）| 乾淨 | 區塊級採樣正常 |
| **fb0 截圖 → 電腦檢視** | **乾淨** | **Qt 渲染鏈 100% 沒問題** |

→ 顯存內容完美但實體螢幕有色點 → 問題發生在 **eLCDIF 與 LCD 驅動 IC 之間**：資料快速翻轉時的訊號完整性 / PCLK 採樣邊緣問題（串擾、地彈、上升沿鈍化）。

### 7.2 修正

| 嘗試 | 修改 | 結果 |
|---------|--------|--------|
| 1. 反轉 PCLK 採樣邊緣 | `pixelclk-active = <0>` → `<1>` | 改善約 50%；**抖動消失** |
| 2. 提高 pad 驅動 + SRE | LCDIF dat/ctrl pinctrl `0x49` → `0x1b0b0` | **完全乾淨** ✅ |

註：`0x49` 是手冊針對 SGM3157 的低驅動建議值；搭配 `pixelclk-active=<1>` 讓採樣相位避開不穩定過渡區，`0x1b0b0`（更快 slew、更強驅動）再讓波形邊緣更陡峭，兩者合作用才完整解決。

## 8. App 部署與 PNG/JPEG 支援

### 8.1 編譯 led + clock App

依規劃只編這兩個 App，兩者用 buildroot 交叉 qmake **一次編譯成功、零錯誤**：

```
cd led/ && output/host/bin/qmake led.pro && make -j8    # → led
cd clock/ && output/host/bin/qmake clock.pro && make -j8 # → clock
```

- 兩者都用 `client.pri`（`QT += remoteobjects` + `REPC_REPLICA`）——套件已具備。
- `QMAKE_POST_LINK` 自動把二進位複製到 `ui/src/apps/`。
- 部署：二進位 → `/opt/ui/src/apps/`；圖示（appicons/*.png）；cfg 配置（第一頁 = LED、第二頁 = clock）。
- 啟動機制驗證：systemui 執行 `/opt/ui/src/apps/<程式名>`（cfg 第三列）。

### 8.2 Dock 配置

`apk3.cfg` 控制底部 Dock（BottomApp 啟動時讀取）：

```
appicons/led.png LED led
appicons/clock.png 时钟 clock
```

Dock 顯示兩個圖示；點擊啟動 App（與頁面相同的啟動路徑）。左右滑動可在頁一 ↔ 頁二切換，Dock 不受影響。

### 8.3 圖示黑色直角問題

轉成 BMP（無 alpha）後，圓角圖示出現**四個黑色直角**——BMP 沒有透明通道，圓角外的透明區被渲染成黑色。

### 8.4 PNG/JPEG 支援（正解）

在 buildroot fragment 加入：

```
BR2_PACKAGE_QT5BASE_PNG=y
BR2_PACKAGE_QT5BASE_JPEG=y
```

重編過程中的發現：
- **PNG 內建於 QtGui**（qpnghandler，不是插件）——沒有 `libqpng.so`；configure 過後直接可用。
- **JPEG 是插件**（`plugins/imageformats/` 的 `libqjpeg.so`）。
- **新增依賴不會自動讓 qt5base 重新 configure**——必須 `make qt5base-dirclean` 後新選項才生效。
- 重建 rootfs（v3）並以 USB + `mmc write` 流程重燒。
- cfg 圖示改回原廠 `.png`——圓角透明正常；背景圖日後也可回 jpg。

### 8.5 字型納入 overlay

字型（DejaVuSans + wqy-zenhei）加入 `rootfs-overlay/usr/lib/fonts/`——之後每次重建 rootfs 都會包含（重燒後不必再手動 scp）。

### 8.6 觸摸交互驗證（第二輪驗證）

- 左右滑動：頁一（LED）↔ 頁二（clock）——流暢。
- 點 LED 圖示：LED 控制介面開啟（「电筒关」）。
- 點 clock 圖示：時鐘介面顯示目前時間。
- 點 Dock 圖示：App 正常啟動。
- 觸摸座標全部正確、無崩潰。

## 9. WiFi 啟用（RTL8188EUS）

### 10.1 調查

USB HUB 上有一支 **Realtek RTL8188EUS** WiFi 網卡（0bda:8179），但沒有驅動/工具（無 `wlan0`、無 wpa_supplicant）。內核已有 `CFG80211=y` + `MAC80211=y`。

### 10.2 內核啟用

`wifi.fragment`：

```
CONFIG_RTL8XXXU=y
```

編譯踩坑：
- **merge_config 不會自動觸發 rtl8xxxu 重編**——需先手動 `make drivers/net/wireless/realtek/rtl8xxxu/`。
- 刪除 `vmlinux` 強制重連結後發生**並行編譯競態**（`drm_gpuva_mgr.o` 缺失 → `ar: Error 123`）——用增量重建 `drivers/gpu/drm/ sound/` 修復，再 `make zImage`。

### 10.3 regulatory.db 之路

- `CFG80211_REQUIRE_SIGNED_REGDB=y` **無法關閉**（Kconfig `default y`）→ 必須提供簽署版 regulatory.db。
- 從 wireless-regdb 官方下載 `regulatory.db` + **`regulatory.db.p7s`**（簽署檔）。
- **時機陷阱**：cfg80211 在 ~3.3 秒初始化，但 rootfs（mmcblk1p2）~3.4 秒才掛載 → 放 rootfs overlay 會載入失敗。
- **解法（與 SDMA firmware 相同）**：用 `CONFIG_EXTRA_FIRMWARE="imx/sdma/sdma-imx6q.bin regulatory.db regulatory.db.p7s"` 內嵌進內核（編譯時檔案必須在 `EXTRA_FIRMWARE_DIR=/lib/firmware`）。

### 10.4 Firmware 與 Rootfs v4

- `rtl8188eufw.bin.zst`（宿主 `/lib/firmware/rtlwifi/`）解壓 → overlay `/lib/firmware/rtlwifi/rtl8188eufw.bin`。
- buildroot 加 `BR2_PACKAGE_WPA_SUPPLICANT=y` → Rootfs v4 → 重燒。
- 開機 log：`RTL8188EU rev D`、`Loading firmware rtlwifi/rtl8188eufw.bin`、`Firmware revision 28.0`。

### 10.5 連線（SSID 誤植教訓）

- 第一次用錯 SSID（**DELL357**）——掃描到 10 個 AP 但都不匹配，「No suitable network found」。
- 正確 SSID 是 **BELL357**（WPA2-PSK）：authenticate → associated → `LOWER_UP` → DHCP `192.168.2.57/24` → `ping 8.8.8.8` **0% 掉包**。
- `eth0`（192.168.1.100）不受影響；wlan0 為並行第二網路。

### 10.6 開機自動連線

`/etc/init.d/S50wifi`（在 overlay）：
1. 等待 `/sys/class/net/wlan0`（≤15 秒）
2. 啟動 `wpa_supplicant -B -i wlan0 -c /etc/wpa_supplicant.conf -D nl80211`
3. 等待 `operstate = up`（≤30 秒）
4. `udhcpc -i wlan0 -q`

`/etc/wpa_supplicant.conf`（BELL357）也在 overlay。腳本已手動測試成功；重開機可確認完整自動連線。

## 11. 重點總結

1. **U-Boot 數字是十六進位**——`mmc write` 的 block 位址一律寫 hex（`0x45000`），不要寫十進位。
2. **絕不可在運行中的 rootfs 上覆蓋部署**——先準備救援系統（USB + ext2 鏡像 + `mmc write` 是最可靠路徑）。
3. **Buildroot Qt5 需要 C++ 工具鏈**——`BR2_TOOLCHAIN_BUILDROOT_CXX=y` 並強制重編 gcc-final。
4. **Qt 5.15 在此平台沒有 GL**——graphicaleffects 不可用；移除沒用的 import/特效，而不是去開 GL。
5. **Framebuffer 截圖除錯**——dump fb0、轉 BMP、電腦檢視，可一舉區分「軟體渲染」與「硬體/訊號」問題。
6. **i.MX6ULL RGB888 顯示噪點**——先試 `pixelclk-active` 反轉，再提高 pinctrl（`0x1b0b0`）；並記得手冊的 SGM3157 驅動能力注意事項。
7. **`scp -O`** 適用於沒有 sftp-server 的 dropbear 板子；每次重燒 rootfs 後要更新 `authorized_keys` 與 host key。
8. **Qt 5.15 的 PNG 內建於 QtGui**（非插件），而 **JPEG 是插件**（`libqjpeg.so`）——動手前先確認真正的機制。
9. **新增 qt5base 選項需要 `make qt5base-dirclean`**——只加依賴不會觸發重新 configure。
10. **重燒 rootfs 會清掉所有執行期修改**——字型/金鑰/UI 微調都要放進 buildroot overlay，不能只改板子。
11. **早期載入的 firmware 必須內嵌進內核**（`CONFIG_EXTRA_FIRMWARE`）——rootfs（mmcblk1p2）掛載太晚，cfg80211/SDMA 載不到（regulatory.db 還需要它的簽署檔 `.p7s`）。
12. **`CONFIG_RTL8XXXU` merge 後需手動重編**——刪除 vmlinux 全量重編可能觸發並行競態（用增量重建失敗目錄修復）。
13. **RTL8188EUS 僅支援 2.4GHz**——5GHz AP 看不到；除錯前務必先確認 SSID 字串正確。
